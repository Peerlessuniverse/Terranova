# Technical Design — proposed synchronization contract
Not replacement for unseen repository TECHNICAL_DESIGN. Local Python standard-library server + SQLite baseline, loopback. Keep current renderer until measured. Domain services catalog, inventory, ledger, settlement, market, transport, crop, energy, progression, event, profile, media, admin. All authority server; UI sends IDs and qty not price or reward. Transaction: validate auth/version/idempotency -> lazy settle max 8h -> check stock/cash/capacity/ownership -> ledger entries + state + receipt -> commit. No per-player jobs every second. Deterministic slot spawn with capped catchup; server time UTC, schedules Asia/Jakarta. Integer grams/GC/Wh, rounding remainder preserved. Energy flow attribution follows 06/07; no storage double count. Async beta Postgres transactional locks/RLS and authenticated APIs after audit. No WebSocket avatar.

Admin minimal local config editor or validated config file, beta RBAC admin/editor/support/read-only; versioned config drafts, validation, publish audit, rollback future config only, no silent retroactive ledger rewrite. Price, spawn, reward, events, sponsor placement, catalog status. No exposed secrets or arbitrary SQL. Feedback local form/export, beta rate limit and consent; bug, suggestion, factual error, rating, optional screenshot sanitized. Action errors code+reason+suggested next step. Knowledge Center links owner book if URL provided; educational content source/year and simulation label. Dynamic events deterministic server calendar with seed, caps, safe weather impacts and alternate mission windows, no hidden disaster purchase pressure. Restore cash via free pickup, affordable NPC service, sell used tools/lease, no cash grant exploit. Used valuation versioned, no buy/sell arbitrage, ownership and maintenance checked; peer rental beta escrow/settlement review.

Endpoint contract proposals (map existing /aksi /state; do not rename blindly): catalog query cursor/version; quote and confirm; market listing; transport reserve/receive; crop plant/harvest/consume; placement validate/commit; energy settle; achievement history/claim; admin config validate/publish; feedback; beta profile/rank/verify/payment webhook. Auth, CSRF, rate limits, input size, idempotency, audit. No public server.py deployment. Google login and public payment require production architecture and legal review.
